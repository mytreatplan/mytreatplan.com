- (decision) A1 paradigm: regional systems of record + central control site (hub and spoke). Each regional instance owns all doctor and patient data of its region (profile, patients, orders, invoices, cases, records); the admin site owns definitions (catalogue, subscriptions, billing rules, vouchers, country map, staff, calendars) and keeps read copies it may store (client record, accounting copy, business figures); shows patient data live from the region, never stored. Each repo is a modular Django monolith; writes go through each app's service.py. Prevents: two owners of one entity; central DB replication. User agreed 2026-10-29
- (decision) A2 interface over HTTPS+JSON, no broker: config = instance pulls a versioned snapshot from admin periodically and on admin nudge; events + accounting feed = transactional outbox table in the instance, dispatched by a job with retries until acknowledged (at-least-once, idempotent on event uuid); remote access = admin calls instance API server-side and renders without persisting (no DB, no cache). User agreed 2026-10-29
- (decision) A3 trust: every interface request carries a short-lived token signed with the sender's Ed25519 key (per-site key pairs, only public keys exchanged); nginx allowlists the peer IPs on interface paths; remote-access tokens carry admin user uuid, role and permitted regions; the instance enforces permission and writes the access log itself. Rejected mTLS (kept only for OVH KMS). User agreed 2026-10-29
- (decision) A4 ids: every record crossing sites is identified by a UUID; integer pks never leave an instance; existing tables keep integer pk and gain a uid UUID field; new tables use UUID pk. Patient code = region prefix + 8 random chars from a no-look-alike alphabet (e.g. EU-7K3QX9MD), generated once, never reused, not derivable; used on invoices, accounting copy, wholesale. User agreed 2026-10-29
